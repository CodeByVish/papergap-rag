# BM25: finding paper chunks related to a question

BM25 is selected for this chunk-size experiment. This guide explains the idea, inputs, outputs and current P3 workflow. Chinese version: [BM25.md](BM25.md).

## 1. Main idea

BM25 splits a question and candidate chunks into words, scores each chunk by matching words, and ranks higher scores first. It requires no model training or weights and does not generate answers.

It considers three things:

1. **How distinctive a word is**: a question word appearing in few chunks usually helps identify relevant content more than one appearing almost everywhere.
2. **How often it appears in a chunk**: with a positive word weight, more occurrences usually increase the score, but the benefit gets smaller. Ten occurrences do not simply earn ten times the score of one occurrence.
3. **How long the chunk is**: longer chunks have more opportunities to contain matching words. Length adjustment reduces this advantage; it does not always favor the shortest chunk.

A question containing `dropout` and `overfitting` will usually favor chunks containing those words. A chunk saying `randomly disabling neurons` may be missed despite discussing a related idea. Word matching does not guarantee understanding of synonyms, negation or answer correctness.

## 2. Inputs

Each chunk is a small searchable document. Index construction and querying have separate inputs.

| Stage | Input | Meaning in this experiment |
| --- | --- | --- |
| Build index | Candidate chunks | Produced from `data/processed/papers.jsonl`; grouped by `paper_id`, scored using `text`, identified by `passage_id`. |
| Query | `query` | Original text of a question selected from `data/processed/qa.jsonl`. |
| Query | `paper_id` | Search only the question's paper. |
| Query | `top_k` | Maximum number of returned chunks; fixed at $5$. |

Titles, section names and neighboring IDs remain in the records, but only `text` is scored. Titles and sections receive no separate boost. Answers and annotated evidence do not enter BM25 indexing or scoring; the evaluator separately uses them for question eligibility and checking retrieved evidence.

## 3. Outputs

The result is a list ordered by descending score. Each item contains the original passage, its raw `score`, and a `rank` starting at $1$. P3 converts this to ordered `(passage_id, score)` pairs and looks up full text and source locations by ID.

A score is a ranking value, not a probability of correctness. A score of $2$ does not mean $2\%$ or $100\%$ relevance. Raw scores should not be directly compared across questions, papers or chunk sizes.

There is no minimum score threshold. Zero and negative scores remain eligible. Fewer than $5$ available chunks means all are returned; an unknown paper returns an empty list. Ties use ascending `passage_id`. An all-zero ranking can still return $5$ chunks without identifying relevant evidence.

## 4. Complete workflow

```text
Preparation, independently for each chunk size:
Paper text -> chunks -> group by paper_id -> tokenize -> compute statistics -> index

For each question:
Question text + paper_id + top_k
    -> select that paper's index
    -> tokenize the question
    -> score every chunk in that paper
    -> sort by descending score, then ascending passage ID
    -> return at most top_k chunks

P3 evaluation:
Returned IDs -> full chunks -> compare against annotated evidence -> evidence metrics and word counts
```

### Step 1: prepare chunks

Build separate candidate corpora of approximately $150$, $200$ and $250$ words per chunk, with fixed overlap of $40$ words. Each size and each paper has its own index. BM25 receives existing chunks; it does not choose their boundaries.

### Step 2: tokenize text

Both question and chunk text use `casefold()` followed by `re.findall(r"\w+", text.casefold())`, extracting runs of Unicode word characters, including letters, digits and underscores. For example, `Dropout reduces overfitting.` becomes `dropout`, `reduces`, `overfitting`.

The code does not remove common words such as `the` and `is`, merge `models` with `model`, or replace synonyms. Repeated query words contribute repeatedly.

Chunk sizes and report word counts use a different counting rule: spaces, newlines, tabs and other whitespace separate words, and each continuous non-whitespace span counts as one word without further splitting punctuation inside it. The chunker finds these spans with `\S+`; reports use `len(text.split())` to count words in a chunk or source paragraph, and total retrieved words sum these counts across returned chunks. The experiment's $150/200/250$-word chunk sizes and $40$-word overlap use this unit too.

For example, the same text `A state-of-the-art model.` splits on whitespace into `A`, `state-of-the-art` and `model.`, giving a report word count of $3$. BM25 instead produces `a`, `state`, `of`, `the`, `art` and `model`, giving a chunk length of $6$ in its scoring formula. Both measure the length of the same text using different counting units; the chunk text and boundaries do not change. A paragraph is a source paragraph, whereas a chunk is a retrieval unit produced by the chunker; they need not correspond one to one.

### Step 3: collect statistics within the paper

Record each chunk's length and word frequencies, the number of chunks containing each word, and average chunk length. A word appearing ten times in one chunk still counts as appearing in only one chunk. These statistics are paper-specific, not shared across all papers.

### Step 4: score chunks

For each question word, combine its distinctiveness, its frequency in the candidate chunk, and length adjustment. Sum the contributions for the chunk's total score. A question word absent from the paper's index contributes zero.

### Step 5: rank and return

Score every chunk in the paper, sort by descending score and then ascending passage ID, and return the first $5$. The implementation does not first discard chunks without matching words.

### Step 6: check evidence

P3 maps returned chunks to source text, checks annotated evidence coverage, and counts retrieved words. BM25 does not know where the correct answer is. High word-match scores and complete supporting evidence require separate checks.

## 5. A worked example

Suppose a paper contains only these $5$ chunks, each with $4$ tokens. The query is `dropout overfitting`, with `top_k=5`.

| Passage ID | Text | Matching query words |
| --- | --- | --- |
| `A` | `dropout reduces model overfitting` | `dropout`, `overfitting` |
| `B` | `regularization improves model generalization` | None |
| `C` | `experiments compare training settings` | None |
| `D` | `results show better accuracy` | None |
| `E` | `models use attention layers` | None |

Each query word occurs in only $1$ chunk, so its weight is $\ln((5-1+0.5)/(1+0.5))=\ln 3\approx1.099$. Each occurs once in `A`, whose length equals the average, making the frequency and length factor below exactly $1$.

Thus `A` scores approximately $2.197$ and all other chunks score $0$. The returned order is `A`, `B`, `C`, `D`, `E`. Only `A` has lexical matches; the other four appear because zero-score results are allowed. This illustrates the algorithm, not an experimental result.

## 6. Formula and current implementation

The following formula connects the explanation to the code:

$$
\operatorname{score}(q,d)=\sum_{t\in q}w(t)\frac{f(t,d)(k_1+1)}{f(t,d)+k_1\left(1-b+b\frac{|d|}{\operatorname{avgdl}}\right)}
$$

| Symbol | Meaning |
| --- | --- |
| $q,d,t$ | Question, candidate chunk, and question word; sum over query occurrences, including repetitions. |
| $f(t,d)$ | Occurrences of the word in the chunk. |
| $\lvert d\rvert,\operatorname{avgdl}$ | Tokenized chunk length and average length within the paper. |
| $w(t)$ | Word weight, called inverse document frequency (IDF); a document here means a chunk. |
| $k_1$ | Controls the benefit from repeated occurrences; currently $1.5$. |
| $b$ | Length adjustment strength: $0$ disables it, $1$ uses full proportional normalization; currently $0.75$. |

The project uses `rank_bm25.BM25Okapi`. It computes $\operatorname{IDF}_{raw}(t)=\ln\frac{N-n(t)+0.5}{n(t)+0.5}$, where $N$ is the paper's chunk count and $n(t)$ counts chunks containing the word. Negative raw IDFs are replaced with $\epsilon\times\overline{\operatorname{IDF}_{raw}}$, averaging original IDFs across all distinct words in the paper's index, with $\epsilon=0.25$. This differs from always-positive IDF formulas found in some explanations. A negative average can still produce negative replacement weights and scores. If the entire paper has an empty token vocabulary, project code assigns all chunks zero scores.

| Setting | Current value or behavior |
| --- | --- |
| Mode | `retrieval.mode = "bm25"`, selected for this experiment. |
| Result limit | `top_k = 5`. |
| Algorithm parameters | Library defaults: $k_1=1.5$, $b=0.75$, $\epsilon=0.25$; these three values are not configurable through the current experiment JSON. |
| Scope | The question's paper, with independent statistics per paper and chunk size. |
| Scored text | Chunk `text`, without additional title or section text. |
| Ties | Ascending `passage_id`. |
| Models and reranking | No weights, dense retrieval, RRF fusion or reranking. |

Keep the retrieval mode and parameters fixed while changing chunk size. Different chunk sizes naturally change word frequencies, average lengths and word weights; those changes are part of the effect being measured. Higher raw scores across sizes do not establish better retrieval. Use evidence coverage, retrieved word count and manual readability review on the same question sample.

### Understanding the fraction in the formula

The fraction multiplied by $w(t)$ is a frequency and length factor: it converts a word's occurrence count into a matching strength adjusted for chunk length. It captures two ideas: repeated occurrences help, with diminishing returns, and longer chunks have more opportunities to contain a keyword, so length needs adjustment. Below, $F$ denotes this factor and $f$ abbreviates $f(t,d)$.

**Start with a chunk of average length.** When $|d|=\operatorname{avgdl}$, the length term $1-b+b|d|/\operatorname{avgdl}=1$. Substituting the current $k_1=1.5$ simplifies the fraction to:

$$
F(f)=\frac{f(k_1+1)}{f+k_1}=\frac{2.5f}{f+1.5}
$$

| Word occurrences in the chunk $f$ | Frequency and length factor $F(f)$ |
| --- | --- |
| $0$ | $0$ |
| $1$ | $1$ |
| $2$ | Approximately $1.43$ |
| $5$ | Approximately $1.92$ |
| $10$ | Approximately $2.17$ |

Thus, ten occurrences produce only about $2.17$ times the factor for one occurrence. This happens because $f$ appears in both the numerator and denominator: both grow as the count increases, making each additional occurrence less beneficial. For a fixed chunk length, the factor approaches $k_1+1=2.5$ as $f$ increases, rather than growing without limit.

The numerator's $(k_1+1)$ also provides a useful reference point: one occurrence in a chunk of average length gives a factor of exactly $1$, so the word contributes exactly $w(t)$ to the score.

**Next, consider how length changes the denominator.** Denote the length adjustment by $L$ and substitute the current $b=0.75$:

$$
L=1-b+b\frac{|d|}{\operatorname{avgdl}}=0.25+0.75\frac{|d|}{\operatorname{avgdl}},\qquad F(f,L)=\frac{2.5f}{f+1.5L}
$$

Suppose the keyword occurs once in each case, so $f=1$:

| Chunk length | Length term $L$ | Factor $F(1,L)$ |
| --- | --- | --- |
| Half the average | $0.625$ | Approximately $1.29$ |
| Equal to the average | $1$ | $1$ |
| Twice the average | $1.75$ | Approximately $0.69$ |

For the same single occurrence, a keyword in a shorter chunk usually suggests more concentrated content. A longer chunk therefore produces a larger $L$ and denominator, reducing the factor. This comparison holds word frequency constant; actual ranking also depends on other query words and their weights, so shorter chunks do not always rank first. Length here counts BM25 tokens, rather than the whitespace-separated words used in experiment reports.

**Finally, reconnect this to the total score.** Each query word contributes its distinctiveness $w(t)$ multiplied by its frequency and length factor $F(f,L)$, and all query-word contributions are summed. For example, a word with weight $2$ occurring twice in an average-length chunk contributes approximately $2\times1.43=2.86$.

The intuition that a larger factor increases the score applies when $w(t)>0$. The current implementation can produce negative weights; in that case a larger factor makes the word's contribution more negative. A zero weight always gives a zero contribution.
